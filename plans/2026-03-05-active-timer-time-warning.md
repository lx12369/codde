# /plan：正在计时预警 + 桌号必填唯一

- 计划日期：2026-03-05
- 对应规格：`specs/2026-03-05-active-timer-time-warning.md`

## 1. Scope / Out-of-scope
### Scope
- 在“开始计时”流程新增桌号字段，并要求必填、格式为 `桌+数字`、active 内唯一。
- 在“正在计时”页面新增限时套餐预警：
  - `limited1h`：50 分钟提醒一次；关闭后不再提醒。
  - `limited2h`：110 分钟提醒一次。
- 提醒形式：语音播报 + 网页弹窗（手动关闭）。
- 提醒文案需包含桌号与剩余时间；无桌号时降级客户名。
- 增加提醒去重与刷新后不重复策略（本地持久化）。

### Out-of-scope
- 不改计费规则、结算公式与消费金额逻辑。
- 不引入后端定时任务/WebSocket 推送。
- 不新增第三方依赖。
- 不做自动桌号编排。

## 2. Implementation Steps (Ordered / Verifiable / Reversible)
### Step 1：补齐桌号数据通路（前后端）
- 目标：计时数据包含桌号字段，新增/编辑可提交并返回。
- 变更要点：
  - `backend/models/models.py`：若缺字段，补 `table_no`（或既有同义字段映射）。
  - `backend/routes/active_timers.py`：创建/更新/查询接口读写桌号。
  - `frontend/src/views/ActiveTimers.vue`：新增/编辑表单绑定桌号。
- 可验证：创建计时后列表可看到桌号；刷新后桌号仍在。
- 可回滚：撤销 `table_no` 读写与前端绑定，恢复旧结构。

### Step 2：实现桌号校验（必填 + 格式 + 唯一）
- 目标：开始计时时必须选桌号，且符合规则并唯一。
- 变更要点：
  - 前端校验：
    - 必填；
    - 正则 `^桌[0-9]+$`；
    - 与其他 active 计时单去重（编辑时排除自身）。
  - 后端二次校验：并发情况下仍保证唯一，返回明确错误信息。
- 可验证：空桌号/非法格式/重复桌号均被拦截并提示。
- 可回滚：移除校验分支与提示文案。

### Step 3：实现计时预警引擎
- 目标：按套餐规则触发提醒并去重。
- 变更要点：
  - 基于 `nowTimestamp` ticker 计算已用分钟。
  - 里程碑映射：
    - `limited1h` -> `[50]`
    - `limited2h` -> `[110]`
  - 命中后进入提醒队列，避免并发弹窗冲突。
  - 关闭弹窗即标记该计时单已提醒，不再重复。
- 可验证：对应分钟点触发一次；关闭后不重复；刷新后不重复。
- 可回滚：移除提醒引擎与队列逻辑。

### Step 4：接入提醒呈现（语音 + 弹窗）
- 目标：提醒可感知且可手动关闭。
- 变更要点：
  - 语音：`speechSynthesis` 播报“桌号 + 剩余时间”（缺桌号降级客户名）。
  - 弹窗：展示桌号、客户、套餐、剩余时间、触发时刻；仅手动关闭。
  - 语音失败降级：仅弹窗并记录 console。
- 可验证：有声+有窗；关闭后消失；不自动关闭。
- 可回滚：移除语音调用与弹窗组件，保留基础页面。

### Step 5：回归与边界验证
- 目标：确认新能力不影响旧流程。
- 校验点：
  - 计时新增、编辑、结算流程正常；
  - 不限时套餐不触发预警；
  - 计费与消费结果不受影响。
- 可回滚：按步骤回滚最近改动（优先 Step 4/3）。

## 4. Manual Validation Checklist
1. 开始计时不填桌号，提交应失败并提示必填。
2. 桌号输入 `A1` 提交应失败，输入 `桌1` 可通过格式校验。
3. 已有 active 使用 `桌1` 时，再开一单 `桌1` 应提示“桌号已占用”。
4. `limited1h` 运行到约 50 分钟触发语音+弹窗，关闭后继续到 110 分钟不再提醒。
5. `limited2h` 运行到约 110 分钟触发语音+弹窗一次。
6. 刷新页面后，已提醒计时单不重复触发。
7. 完成结算后，相关计时单不再进入提醒判断。

## 5. Execution Notes
- 若现有数据库无 `table_no` 字段，先在模型初始化迁移逻辑中做向后兼容补列。
- 唯一性以 active 计时单为准；编辑自身桌号不应判冲突。
- 语音播报需容忍浏览器策略限制，失败不阻断弹窗提醒。
