# /plan：计费规则、正在计时、客户管理页面联合美化执行计划

## 1. 关联规格
- Spec：[`specs/2026-03-04-billing-active-timers-customers-page-beautification.md`](../specs/2026-03-04-billing-active-timers-customers-page-beautification.md)

## 2. 范围与非范围
### Scope
- 仅改造以下三个页面的前端表现层与交互层级，不改后端契约：
  - `frontend/src/views/Billing.vue`
  - `frontend/src/views/ActiveTimers.vue`
  - `frontend/src/views/Customers.vue`
- 三页统一落地“头部总览 + 主操作区 + 内容区 + 反馈区”结构。
- 保持既有业务流程全量可用：计费规则读写、计时增改停续结算结束、客户增改删/充值/消费/批量删除。
- 补齐加载中、空数据、请求失败、提交成功/失败的可见反馈，减少分散 `alert/confirm` 依赖。
- 完成 375px 与 >=1280px 响应式收口，保证关键操作可见可点、布局不拥挤。

### Out of Scope
- 不修改任何后端路由、数据库模型、业务计算规则。
- 不新增第三方依赖，不修改 `package.json`、各类 lock 文件或 Python 依赖文件。
- 不改造本计划之外页面（如 Dashboard、SystemLogs、Transactions 等）。

## 3. 执行前提
- 本文档定义 `/do` 阶段执行步骤；当前阶段仅产出计划文档，不改源码。
- `/do` 必须按本计划顺序执行；若出现计划外需求，先回到 `/plan` 更新后再实施。
- 视觉方向以现有后台统一风格为准，优先对齐“数据管理/系统日志”已落地的头部与反馈语义。
- 若本地缺少依赖，先由用户执行安装命令并提供输出后继续。

## 4. 分步实施（有序、可验证、可回退）
### Step 1：梳理不可变业务契约与页面现状（AC2, AC4, AC6, AC7）
- 操作：
  - 盘点三页数据流：请求参数、返回字段、关键状态变量、按钮触发链路。
  - 标记不可变契约：接口路径、字段名、ID 语义、关键行为（例如筛选后分页、结算后刷新）。
- 验证：
  - 输出“三页不可变逻辑清单 + 可改造 UI 清单”，并与现有函数映射。
- 回退：
  - 纯分析步骤无代码改动，无需回退。

### Step 2：统一三页页面骨架与视觉基线（AC1, AC11）
- 操作：
  - 在三页统一头部总览容器、标题层级、辅助说明、主操作入口排布。
  - 统一区块间距、卡片圆角/边框/阴影、按钮尺寸与禁用态、输入控件焦点态。
- 验证：
  - 三页首屏结构一致，用户可快速识别“页面定位 + 主动作 + 内容区”。
- 回退：
  - 若统一样式影响可读性，逐页回退样式层，不回退业务逻辑。

### Step 3：改造 Billing 页面信息层级与表单可读性（AC2, AC3）
- 操作：
  - 重构 `Billing.vue` 分区结构（限时套餐/工作日周末/素材费用/加班费用）为清晰分组卡片。
  - 统一字段标签、输入宽度、行高与说明文案位置，突出“保存规则”主操作。
  - 接入统一成功/失败反馈条，替代零散提示。
- 验证：
  - `GET /billing-rules` 加载正常；`PUT /billing-rules` 保存成功后反馈可见且数据回写正确。
- 回退：
  - 若样式改造影响字段编辑，先回退分组样式并保留稳定的保存链路。

### Step 4：改造 ActiveTimers 页面筛选与卡片层级（AC4, AC5, AC9）
- 操作：
  - 优化筛选区字段排布和按钮主次关系，保持查询语义不变。
  - 重排计时卡片信息层级，突出关键字段（客户、项目、状态、时长、金额）。
  - 统一新增/编辑/结算弹窗底栏按钮顺序、风险色语义、提交中禁用态。
- 验证：
  - 筛选、暂停/继续、编辑、结算、结束流程全部可用且无行为回归。
- 回退：
  - 若卡片改造影响操作可达性，回退卡片布局并保留弹窗一致性修复。

### Step 5：改造 Customers 页面列表与业务弹窗一致性（AC6, AC7, AC9）
- 操作：
  - 优化客户列表信息密度与操作列层级，突出余额与状态信息。
  - 统一客户详情、新增/编辑、充值、消费、批量删除交互风格。
  - 为高风险操作（删除/批量删除）强化确认语义与错误反馈。
- 验证：
  - 客户查询、详情、新增、编辑、删除、批量删除、充值、消费全链路可用。
- 回退：
  - 若弹窗重构出现回归，分模块回退（详情/充值/消费）到最近稳定版本。

### Step 6：统一三页状态反馈机制（AC8, AC9, AC12）
- 操作：
  - 统一加载中、空态、失败、成功反馈的展示位置和文案风格。
  - 避免仅依赖控制台错误；失败时提供同层可见提示和重试入口（适用处）。
- 验证：
  - 三页均可稳定观察到四类状态反馈；网络失败时有可见提示。
- 回退：
  - 若反馈层干扰主流程，先保留失败提示并简化动效/弱化次要反馈。

### Step 7：响应式与可访问性收口（AC10, AC11）
- 操作：
  - 在 375px 下优化按钮换行、表单与卡片宽度、弹窗内容滚动与底栏可见性。
  - 在 >=1280px 下提升信息密度，避免区块拉伸过度或拥挤。
  - 确保键盘可达、焦点可见、文本对比度达标。
- 验证：
  - 小屏可完成核心操作且无遮挡/严重溢出；大屏层级清晰且可扫描。
- 回退：
  - 若移动端方案不稳定，回退到保守单列布局并保留关键可读性优化。

### Step 8：构建与手工回归验收（AC1-AC12）
- 操作：
  - 执行前端构建验证。
  - 启动前后端联调，按 AC1-AC12 对三页逐项手工验收并记录结果。
- 验证：
  - 构建通过；关键流程无新增未处理异常；验收项满足或记录差异与修复闭环。
- 回退：
  - 若出现阻塞问题，按页面粒度回滚到改造前稳定版本并分批重做。

## 7. 风险与应对
- 风险：`ActiveTimers.vue` 与 `Customers.vue` 状态分支复杂，样式重排可能触发交互回归。
  - 应对：每页按“结构层 -> 交互层 -> 反馈层”渐进改造，并逐步验收。
- 风险：统一反馈机制时遗漏边缘失败分支。
  - 应对：为关键异步操作逐项检查 success/error/finally 分支，补齐可见提示。
- 风险：移动端布局优化引入弹窗遮挡或操作区拥挤。
  - 应对：以 375px 为最低断点逐页验收，必要时采用更保守布局策略。
