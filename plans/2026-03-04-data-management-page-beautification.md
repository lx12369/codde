# /plan：数据管理页面美化执行计划

## 1. 关联规格
- Spec：[`specs/2026-03-04-data-management-page-beautification.md`](../specs/2026-03-04-data-management-page-beautification.md)

## 2. 范围与非范围
### Scope
- 仅改造 `frontend/src/views/Settings.vue`，围绕 `/settings` 页面进行视觉与交互优化。
- 保持后端接口契约不变，仅复用：
  - `/api/data/storage-info`
  - `/api/data/backup`
  - `/api/data/restore`
  - `/api/data/clear`
- 实现目标包含：
  - 信息架构重排（状态总览 / 常规操作 / 危险操作）
  - 中文文案乱码修复
  - 统一加载/成功/失败反馈
  - 移动端与桌面端布局优化

### Out of Scope
- 不修改后端逻辑与数据模型（`backend/routes/data.py` 及相关模型）。
- 不新增依赖，不修改 `package.json`、lock 文件或其他依赖声明。
- 不改动 `Settings.vue` 之外的业务页（如 `Customers.vue`、`Transactions.vue`）。

## 3. 执行前提
- 本文档仅定义实施计划，不在本阶段修改业务源码。
- `/do` 阶段按本计划执行；如出现计划外需求，先回到 `/plan` 更新。
- 若本地缺失依赖，由用户执行安装命令并粘贴输出后继续。

## 4. 分步实施（有序、可验证、可回退）
### Step 1：收敛现有状态与交互分支
- 操作：
  - 梳理 `Settings.vue` 当前状态变量与接口调用链（`fetchDataStatus`、`backupData`、`restoreData`、`clearAllData`）。
  - 明确保留逻辑（接口调用/文件下载/JSON 校验）与待替换逻辑（乱码文案、零散 `alert` 反馈）。
- 验证：
  - 能形成“保留项/替换项”清单，且每项都能映射到具体代码块。
- 回退：
  - 仅分析不改动，无需回退。

### Step 2：修复文案与状态语义（P0）
- 操作：
  - 修复页面标题、卡片文案、按钮文案、弹窗文案、错误提示中的乱码。
  - 统一操作状态文案（空闲/处理中/成功/失败），并确保三类操作语义一致。
- 验证：
  - 页面中所有可见文本均为可读中文；无乱码字符。
- 回退：
  - 若出现局部文案回归，可回退对应文案块并逐段恢复。

### Step 3：重构页面信息架构与视觉层级（P0/P1）
- 操作：
  - 重排模板结构为：
    - 顶部说明区（标题 + 辅助说明 + 刷新状态）
    - 数据状态区（存储位置/数据大小/客户数/交易数）
    - 常规操作区（备份、恢复）
    - 危险操作区（清空数据）
  - 优化卡片间距、对齐、按钮层级，减少移动端误触。
- 验证：
  - 375px 下无横向滚动；>=1280px 下分区清晰，按钮不拥挤。
- 回退：
  - 若布局风险高，先回退样式层改动，保留脚本逻辑与文案修复结果。

### Step 4：统一反馈机制与错误处理（P0）
- 操作：
  - 将备份/恢复/清空反馈统一为可感知状态（按钮禁用 + 进行中提示 + 结果提示）。
  - 保持恢复 `.json` 文件校验，补充“格式错误/请求失败”可读提示。
  - 保留并强化清空数据二次确认（高风险视觉与明确后果提示）。
- 验证：
  - 三类操作都存在完整状态闭环，失败路径无“静默失败”。
- 回退：
  - 如统一反馈导致交互异常，可先恢复原操作流程，再逐项替换反馈层。

### Step 5：可访问性与交互细节收敛（P1/P2）
- 操作：
  - 优化弹窗焦点与按钮主次，保证键盘可达与焦点可见。
  - 增加轻量过渡效果（卡片/按钮状态变化），控制动画强度避免干扰。
- 验证：
  - 键盘可触达关键操作；弹窗开关逻辑稳定；无明显视觉跳变。
- 回退：
  - 若动画影响可用性，回退过渡类名，仅保留静态样式。

### Step 6：构建与手工验收
- 操作：
  - 运行构建验证。
  - 启动前后端进行 `/settings` 手工验收，按 AC1-AC8 逐条检查。
- 验证：
  - 构建通过，页面可正常完成备份/恢复/清空流程，控制台无新增未处理异常。
- 回退：
  - 若构建或关键流程失败且短时无法修复，回退 `Settings.vue` 到改造前稳定版本并重新拆分改动。

```

预期结果：前端启动成功，可访问 `/settings` 并完成交互验收。

```

## 6. 验收清单（映射 Spec AC）
- AC1：页面全部可见文案为可读中文，无乱码。
- AC2：状态区展示存储位置、数据大小、客户数、交易数，并有加载态。
- AC3：备份按钮触发下载，处理中禁用且有进行中提示。
- AC4：非 `.json` 上传被拦截并有明确错误提示。
- AC5：恢复成功后自动刷新状态并展示成功反馈。
- AC6：清空操作具备二次确认与高风险视觉提示，执行后刷新状态。
- AC7：375px 与 >=1280px 下布局可用且无明显拥挤/溢出。
- AC8：完整流程中无新增未处理异常（网络失败除外，但需可见错误反馈）。

## 7. 风险与应对
- 风险：文案修复遗漏，局部仍有乱码。
  - 应对：完成后逐区块通读并结合手工点击全流程检查。
- 风险：视觉重排影响现有布局一致性。
  - 应对：保持 `MainLayout` 风格基线，不改全局样式体系。
- 风险：统一反馈改造引入状态竞争（多个 loading 交叉）。
  - 应对：按操作维度拆分状态变量，避免共享 loading 标记。
