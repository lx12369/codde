# /plan：正在计时页复用交易记录计时消费弹窗执行计划

## 1. 关联规格
- Spec：[specs/2026-03-04-active-timers-shared-timer-consume-dialog.md](../specs/2026-03-04-active-timers-shared-timer-consume-dialog.md)

## 2. 范围与非范围
### Scope
- 统一“启动计时消费”弹窗实现：让 `ActiveTimers.vue` 的“新增消费”使用与 `Transactions.vue` 的“计时消费模式”一致的窗口逻辑。
- 优先抽离复用单元（组件或复用逻辑），并在两个页面接入。
- 对齐字段、默认值、联动、校验、提交 payload、关闭行为和反馈行为。
- 保持 `POST /active-timers` 接口契约不变。

### Out of Scope
- 不修改后端接口、数据库、计费规则、结算规则。
- 不将“交易记录页”手动消费/自动结算模式迁移到“正在计时页”。
- 不修改依赖声明和 lock 文件，不执行自动安装依赖。
- 不重构“正在计时页”列表、编辑、结算等与本需求无关的 UI。

- 当前阶段仅执行计划文档，不改源码。
- `/do` 阶段仅按本计划实施；若需新增步骤，先回到 `/plan` 更新。

## 4. 分步实施（有序、可验证、可回退）
### Step 1：确认两处计时消费逻辑差异并冻结接口契约
- 操作
  - 梳理 `Transactions.vue` 计时消费模式与 `ActiveTimers.vue` 开始计时弹窗的字段、默认值、校验、payload 构造。
  - 确认两处提交契约统一为 `POST /active-timers` + `notes` JSON（`note/packagePlan/materials`）。
- 验证
  - 输出差异清单，并标记“必须统一项”和“页面保留项”。
- 回退
  - 纯分析步骤，无代码回退成本。

### Step 2：抽离可复用的计时消费弹窗实现
- 操作
  - 新建复用弹窗单元（建议：`frontend/src/components/timers/TimerConsumeDialog.vue`）。
  - 将计时消费表单 UI、计时类型与套餐联动、非负数输入约束、校验提示抽离为组件内部或受控 props/events。
  - 约定组件输入输出契约（如 `modelValue`、`initialCustomerId`、`submitting`、`confirm/cancel` 事件）。
- 验证
  - 组件具备独立渲染能力，字段完整覆盖客户/计时类型/套餐/素材数量/备注。
- 回退
  - 若抽离导致耦合过高，回退新增组件文件，改为先抽离共享函数并保留页面模板最小改动。

### Step 3：在交易记录页接入复用弹窗（仅计时消费模式）
- 操作
  - 将 `Transactions.vue` 的第 3 模式表单替换为复用弹窗。
  - 保持页面既有模式切换框架不变，仅替换“计时消费模式”区域与提交入口绑定。
  - 保持 `submitTimerConsume` 业务语义不变（或迁移到共享提交函数后保持结果一致）。
- 验证
  - 在交易记录页切到“计时消费”时，字段、默认值、校验、提交行为与改造前一致。
- 回退
  - 若影响其他消费模式，先回退 `Transactions.vue` 接入改动，保留抽离组件继续迭代。

### Step 4：在正在计时页“新增消费”接入同一复用弹窗
- 操作
  - 将 `ActiveTimers.vue` 现有“开始计时”弹窗替换为复用弹窗。
  - 映射页面状态：打开/关闭、新增提交中状态、提交成功后刷新 `fetchTimers()`。
  - 保持原“新增消费”入口按钮与页面主流程不变。
- 验证
  - `/active-timers` 点击“新增消费”后弹窗与交易记录页第 3 模式一致，提交成功后刷新列表。
- 回退
  - 若刷新或关闭时机异常，回退 `ActiveTimers.vue` 接入层，保留复用单元待修正。

### Step 5：统一关闭与反馈行为（含 ESC/遮罩/取消）
- 操作
  - 对齐两页弹窗关闭行为：`ESC`、遮罩点击、取消按钮。
  - 对齐失败反馈策略：至少保证错误可见，不出现“失败却关闭弹窗”。
  - 保证提交中禁用状态一致，防止重复提交。
- 验证
  - 触发失败分支时弹窗仍在且错误可见；成功分支关闭并刷新对应数据。
- 回退
  - 若通用关闭行为影响页面其他弹窗，回退关闭策略到页面局部实现，再逐项恢复。

### Step 6：构建与回归验收
- 操作
  - 执行前端构建。
  - 手工回归两页关键路径：打开、填写、校验、提交成功、提交失败、关闭行为。
  - 回归“正在计时”其他功能：暂停/继续、编辑、结算是否受影响。
- 验证
  - 构建通过；AC1-AC8 全部通过。
- 回退
  - 若出现阻塞问题，按“新增文件 -> 接入文件”的顺序回退到上一个稳定点。

## 6. 验收清单（映射 Spec AC）
- AC1：`/active-timers` 新增消费弹窗形态与 `/transactions` 第 3 模式一致。
- AC2：两处默认值与联动规则一致（含计时类型切换后套餐默认值）。
- AC3：两处校验规则一致，提示触发时机一致。
- AC4：两处都调用 `POST /active-timers`，`notes` 结构一致。
- AC5：`/active-timers` 提交成功后关闭并刷新列表；失败时错误可见且不误关闭。
- AC6：ESC、遮罩、取消按钮可正常关闭弹窗。
- AC7：正在计时页原有编辑/暂停继续/结算功能回归通过。
- AC8：前端构建通过，控制台无新增未处理异常（网络错误除外）。

## 7. 风险与应对
- 风险：复用后两页状态管理耦合导致某页行为回归。
  - 应对：保持“页面负责状态、复用单元负责呈现+局部校验”的边界。
- 风险：弹窗关闭和焦点行为在双页上下文不一致。
  - 应对：将关闭触发条件与事件命名标准化，优先保证可预测关闭路径。
- 风险：提交逻辑抽离后列表刷新时机错误。
  - 应对：提交成功后刷新动作由页面侧负责，不放入通用组件。
