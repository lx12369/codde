# /plan：仪表盘内容充实执行计划

## 1. 关联规格
- Spec：`specs/2026-03-04-dashboard-content-enrichment.md`

## 2. 范围与非范围
### Scope
- 仅改造 `frontend/src/views/Dashboard.vue`，在现有核心版基础上补充展示内容。
- 必须保留：
  - 计费日类型显示与切换。
  - 刷新按钮逻辑。
  - 今日消费金额、今日消费人数两项核心指标。
- 新增模块目标：
  - 运营总览（4+ 指标）
  - 结构洞察（比率/对比摘要）
  - 最近活动（精简展示）
  - 快捷入口（高频页面导航）

### Out of Scope
- 不修改后端接口与统计口径（`backend/routes/dashboard.py`）。
- 不改动依赖文件（`package.json`、lock 文件等）。
- 不调整非仪表盘页面业务逻辑。

## 3. 执行前提
- 本文档仅定义执行步骤，不在本阶段改源码。
- `/do` 阶段按本计划实施；若出现计划外改动需求，先回到 `/plan` 更新。

## 4. 分步实施（有序、可验证、可回退）
### Step 1：收敛数据模型与模块骨架
- 操作：
  - 在 `Dashboard.vue` 中整理状态结构，定义：
    - 核心指标状态（消费金额/人数）
    - 总览指标状态（客户总数、充值相关、交易总数、活跃计时等）
    - 最近活动列表状态
    - 全局加载/局部错误状态
  - 统一接口结果解析函数，兼容 `response.data` 与平铺对象。
- 验证：
  - 状态命名与字段映射可直接对应 API 字段。
- 回退：
  - 仅状态层改动可单文件回退 `Dashboard.vue`。

### Step 2：扩展 refreshData 数据拉取流程
- 操作：
  - 维持原有计费日同步逻辑。
  - 将刷新流程改为并行拉取：
    - `/dashboard/stats`
    - `/dashboard/recent-activities`
  - 增加失败降级：单模块失败不导致整页崩溃。
- 验证：
  - 任一接口失败时，其他模块仍可渲染；可见错误提示。
- 回退：
  - 回退 `refreshData` 到仅拉取 stats 版本。

### Step 3：实现“运营总览 + 结构洞察”展示
- 操作：
  - 新增运营总览卡片区（至少 4 项 stats 字段）。
  - 新增结构洞察区（如消费/充值金额占比、消费人次/消费笔数摘要）。
  - 使用轻量可视化（进度条或比例文本），不新增图表依赖。
- 验证：
  - 总览卡字段标签和值映射正确，洞察区能随数据变化。
- 回退：
  - 如洞察区风险高，先回退洞察区样式和计算，保留总览卡。

### Step 4：实现“最近活动 + 快捷入口”展示
- 操作：
  - 新增最近活动列表（展示最近若干条、时间/类型/描述简化字段）。
  - 新增快捷入口卡片/按钮（跳转 Customers、Transactions、ActiveTimers 等）。
  - 补充空态文案和错误态提示。
- 验证：
  - 有数据时显示列表，无数据时显示空态；快捷入口可正常跳转。
- 回退：
  - 回退最近活动模块或快捷入口模块，保留核心与总览模块。

### Step 5：响应式与可用性收敛
- 操作：
  - 调整模块布局在 `360px`、平板、桌面下的网格与间距。
  - 确保按钮触达尺寸、加载态禁用、文本可读性。
- 验证：
  - 无明显横向滚动；交互按钮可点击，加载态合理。
- 回退：
  - 回退布局样式类名到上一步稳定版本，保留数据逻辑不动。

### Step 6：构建与验收
- 操作：
  - 执行前端构建检查。
  - 本地联调检查 AC1-AC7。
- 验证：
  - 构建通过、页面无报错、关键交互通过。
- 回退：
  - 如出现阻塞问题，回退 `Dashboard.vue` 至上一稳定提交或本地备份版本。

## 6. 验收清单（映射 Spec AC）
- AC1：计费日类型与切换按钮可见且可用。
- AC2：核心双 KPI（今日消费金额/人数）显示正确且来自 stats。
- AC3：新增至少 3 个非核心模块且内容非占位。
- AC4：运营总览至少 4 个 stats 字段映射正确。
- AC5：最近活动支持正常态、空态、错误态。
- AC6：360px 与桌面宽度下无明显横向溢出。
- AC7：`npm run build` 通过，运行无明显报错。

## 7. 风险与应对
- 风险：新增模块过多造成视觉拥挤。
  - 应对：按“核心 > 总览 > 辅助”层级控制密度，必要时收敛字段数量。
- 风险：多接口并行导致异常路径复杂。
  - 应对：模块级错误状态独立，不让单点失败拖垮整页。
- 风险：最近活动字段格式不统一影响展示。
  - 应对：增加展示层标准化函数，未知字段给兜底文本。
