# /plan：系统日志页面美化执行计划

## 1. 关联规格
- Spec：[`specs/2026-03-04-system-logs-page-beautification.md`](../specs/2026-03-04-system-logs-page-beautification.md)

## 2. 范围与非范围
### Scope
- 仅改造 `frontend/src/views/SystemLogs.vue`，目标是优化 `/system-logs` 的视觉层级、筛选体验、日志可读性与状态反馈。
- 保持后端接口契约不变，仅复用既有日志接口：
  - `/api/logs`
- 计划内必须落地：
  - 页面结构重组（头部总览 + 筛选区 + 日志区 + 分页区）。
  - 统一加载/空态/失败反馈。
  - 保持筛选、分页、刷新行为与现有语义一致。

### Out of Scope
- 不修改 `backend/routes/logs.py`、日志模型、日志类型映射或数据库结构。
- 不新增依赖，不修改 `package.json`、lock 文件或 Python 依赖文件。
- 不改造 `SystemLogs.vue` 之外的业务页面。

## 3. 执行前提
- 本文档定义 `/do` 的可执行步骤；当前阶段不直接修改源码。
- `/do` 必须按本计划执行；出现计划外需求时先回到 `/plan` 更新。
- 若依赖缺失导致命令失败，需用户执行安装命令并粘贴输出后继续。

## 4. 分步实施（有序、可验证、可回退）
### Step 1：梳理现有逻辑与不可变契约
- 操作：
  - 梳理 `SystemLogs.vue` 现有流程：筛选参数构建、列表加载、分页计算、页码跳转、刷新行为。
  - 标记不可变契约：`/logs` 参数与返回结构、时间倒序语义、分页逻辑。
- 验证：
  - 输出“保留逻辑清单 + 可重构 UI 清单”，并映射到现有函数。
- 回退：
  - 分析步骤无代码改动，无需回退。

### Step 2：重构头部总览与刷新入口（AC1, AC3）
- 操作：
  - 将头部改造为“标题 + 更新时间 + 刷新按钮 + 辅助说明/统计信息”结构。
  - 统一头部视觉风格，与后台其它页面保持一致。
- 验证：
  - 首屏可快速识别页面用途、最后更新时间与刷新入口。
- 回退：
  - 若头部样式引发布局回归，先回退头部容器样式并保留刷新逻辑。

### Step 3：重构筛选区布局与交互层级（AC2）
- 操作：
  - 重排模块、操作、操作员、关键字四项筛选字段，强化输入可读性和按钮主次。
  - 保持“查询/重置”行为语义不变，查询后强制回到第一页。
- 验证：
  - 任意筛选组合都可正确触发请求，重置可恢复默认筛选并刷新列表。
- 回退：
  - 若筛选布局调整影响交互，回退样式层，保留筛选逻辑代码。

### Step 4：优化日志列表可读性与标签语义（AC4, AC5）
- 操作：
  - 优化表头、行距、列宽与描述字段展示策略，提升扫读效率。
  - 优化模块/操作标签视觉分层，保持现有类型映射逻辑不变。
- 验证：
  - 核心字段完整可读；不同日志类型可通过标签快速区分。
- 回退：
  - 若列宽或截断策略导致信息丢失，回退对应列样式并保留标签优化。

### Step 5：补齐页面状态反馈层（AC6, AC10）
- 操作：
  - 增加统一反馈机制，覆盖加载中、空数据、请求失败场景。
  - 请求失败时提供可见提示与重试入口，不仅记录控制台错误。
- 验证：
  - 可稳定观察三类状态反馈，失败后可执行重试并恢复数据。
- 回退：
  - 若反馈组件引发冲突，优先保留失败提示并简化动效/样式层。

### Step 6：分页区交互与信息密度优化（AC7, AC8）
- 操作：
  - 保留页码、上一页/下一页、每页条数功能，优化视觉与禁用态。
  - 保持“当前页超界自动回退有效页并重新加载”逻辑可用。
- 验证：
  - 页码跳转、页大小切换、边界页禁用、超界回退均行为正确。
- 回退：
  - 若分页样式回归影响功能，先回退分页样式并保留原逻辑。

### Step 7：响应式收口（AC9）
- 操作：
  - 优化 375px 小屏下筛选与列表可读性（卡片化或横向滚动增强提示二选一落地）。
  - 优化 >=1280px 桌面端信息密度，避免列表拥挤。
- 验证：
  - 小屏可完成筛选和翻页；大屏列表层级清晰且字段可读。
- 回退：
  - 若移动端方案不稳定，回退到保守表格方案并保留关键可读性优化。

### Step 8：构建与回归验收（AC1-AC11）
- 操作：
  - 执行前端构建验证。
  - 启动联调并按 AC1-AC11 逐项手工验收。
- 验证：
  - 构建通过；日志页关键流程无新增未处理异常；验收项满足或记录差异。
- 回退：
  - 若出现阻塞问题，回滚 `SystemLogs.vue` 到改造前稳定版本并分批重做。

## 6. 验收清单（映射 Spec AC）
- AC1：页面结构分层清晰（头部/筛选/日志区/分页区）。
- AC2：四项筛选可用，查询与重置行为正确。
- AC3：刷新入口可用，更新时间与列表状态同步。
- AC4：日志字段完整且可读（时间、模块、操作、类型、描述、操作员）。
- AC5：模块与操作标签语义清晰、可快速区分。
- AC6：加载中/空数据/失败状态均有可见反馈。
- AC7：分页交互完整可用，显示范围计算正确。
- AC8：筛选后总页数变化可自动回退到有效页。
- AC9：375px 与 >=1280px 下布局稳定、信息可读。
- AC10：关键流程无新增未处理异常（网络失败除外但需可见提示）。
- AC11：前端构建通过。

## 7. 风险与应对
- 风险：表格重构导致列宽或文本截断回归。
  - 应对：优先确保“字段完整可读”，逐列调优而非一次性大改。
- 风险：反馈层补齐后与现有加载态冲突。
  - 应对：统一状态源（loading/error/empty）并分支渲染。
- 风险：移动端适配策略影响桌面端布局。
  - 应对：按断点分层实现，小屏变更不影响桌面主结构。
