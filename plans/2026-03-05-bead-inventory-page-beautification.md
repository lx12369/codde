# /plan：豆仓管理页面美化执行计划

## 1. 关联规格
- Spec：[`specs/2026-03-05-bead-inventory-page-beautification.md`](../specs/2026-03-05-bead-inventory-page-beautification.md)

## 2. 范围与非范围
### Scope
- 仅改造 `frontend/src/views/BeadInventory.vue` 的页面结构、视觉样式与交互表达。
- 复用系统既有视觉语言（`page-hero`、反馈条、卡片分区、状态色）。
- 保持现有功能与接口契约不变：
  - 豆料管理（增删改、常用色）
  - 入库/损耗/盘点
  - 预警与台账
  - 流水筛选与分页
  - Mard 导入与批量设置弹窗

### Out of Scope
- 不改后端接口/模型/业务校验（`backend/routes/bead_inventory.py` 等）。
- 不新增依赖，不改 `package.json` / lock 文件。
- 不扩展新业务能力（审批流、多仓库、权限细化）。

## 3. 执行前提
- 本文档为 `/do` 阶段执行依据，当前阶段不修改源码。
- 若执行中出现计划外需求，先回到 `/plan` 更新。
- 若本地缺依赖，先由用户执行安装并提供输出后继续。

## 4. 分步实施（有序、可验证、可回退）
### Step 1：梳理现状与样式基线
- 操作：
  - 盘点 `BeadInventory.vue` 现有分区与状态变量。
  - 提取对齐基线（`Settings.vue`、`ActiveTimers.vue` 的 hero、反馈条、卡片模式）。
- 验证：
  - 形成“保留逻辑 / 重构布局 / 统一样式”清单。
- 回退：
  - 分析步骤无代码改动，无需回退。

### Step 2：重构顶部与全局反馈层（P0）
- 操作：
  - 将豆仓页面头部改为统一 hero 样式。
  - 建立统一反馈条（success/error/info），替代分散、突兀提示。
  - 统一顶部操作按钮层级（主次与颜色语义）。
- 验证：
  - 首屏可在 3 秒内理解页面用途与主要操作。
- 回退：
  - 可独立回退 hero/反馈区模板与对应样式块。

### Step 3：重排信息架构与卡片区块（P0/P1）
- 操作：
  - 按“概览 -> 预警 -> 豆料台账 -> 库存操作 -> 流水”重排布局。
  - 优化指标卡、预警条、操作卡的视觉一致性与层级。
  - 强化选中豆料的视觉锚点（台账行 + 操作区上下文同步明显）。
- 验证：
  - 用户能快速识别当前操作对象，误操作风险降低。
- 回退：
  - 若重排影响交互，先回退布局层，保留逻辑与数据绑定。

### Step 4：统一表格与弹窗视觉规范（P0）
- 操作：
  - 豆料台账、流水表格统一头/行/状态样式。
  - 弹窗（新增/编辑、单位换算、批量市场价）统一头部、表单间距、按钮主次与关闭行为。
  - 保持所有字段、校验和提交流程不变。
- 验证：
  - 弹窗风格统一、可读性提升，功能无回归。
- 回退：
  - 弹窗样式可局部回退，不影响业务提交逻辑。

### Step 5：响应式与细节打磨（P1/P2）
- 操作：
  - 适配 375px 与 >=1280px 的布局密度。
  - 增加轻量过渡（卡片进入、按钮 hover/disabled），避免过度动画。
- 验证：
  - 无关键控件遮挡、无明显布局错乱、无额外横向滚动。
- 回退：
  - 若动画/细节影响可用性，回退过渡样式，保留静态样式。

### Step 6：构建与回归验收
- 操作：
  - 执行前端构建。
  - 手工回归：导入 221 色、增删改豆料、入库/损耗/盘点、流水筛选分页。
- 验证：
  - 构建通过且关键流程无回归。
- 回退：
  - 若短时无法修复，整体回退 `BeadInventory.vue` 到改造前稳定版本。

## 7. 风险与应对
- 风险：样式重排影响交互点击区域或数据绑定。
  - 应对：分步骤提交，先结构后样式，每步做手工回归。
- 风险：移动端表格可读性下降。
  - 应对：优先保障关键字段可见，必要时收敛次要字段视觉权重。
- 风险：页面美化后风格偏离系统。
  - 应对：严格复用现有页面视觉 token 与组件风格。
